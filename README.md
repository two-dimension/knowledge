# 砚知 · 二级买方投研知识库

砚知不是一个“把录音扔进去问问题”的聊天机器人，而是一套围绕机构判断形成、验证和复盘的 Research OS。核心闭环是：

`饭局/调研谈话 → 原始材料留存 → 研究员结构化 → 观点与证据关联 → 可证伪验证 → 版本化机构记忆`

## 当前版本已经包含

- 机构投研总览：新谈话、有效观点、验证任务、组合关联和主题信号
- 谈话收件箱：录音/速记上传、场景与信息源登记、敏感等级、合规确认
- 智能填充：粘贴谈话后自动识别主题、行业、标的、人物、摘要和候选观点，结果可人工修改
- 知识库：以“观点卡”而不是文档为中心，显示证据数、信息源、标的、置信度
- 标的与主题：主题信号热度、观点—标的关联矩阵
- 人物网络：专长、历史可靠度、相关谈话；可靠度不等同于头衔权威
- 验证队列：截止时间、负责人、验证动作、状态闭环
- 详情抽屉：核心观点、证据链与原始记录
- 全局搜索、移动端布局、JSON 导出
- 无 Docker 的 D1 轻量混合检索：观点/摘要/原话分层切片、字段权重、时效与置信度重排、原文级引用
- R2 音频对象存储、D1 转写任务状态、说话人时间码逐字稿与结构化候选结果
- D1 结构化持久化；访问与操作审计由公司内部平台统一承接

## 运行

```powershell
npm install
npm run dev
```

打开 `http://localhost:3000`。

如需启用 MiniMax M3，将 `.env.example` 复制为本地环境文件并填写 `MINIMAX_API_KEY`。密钥不得提交到版本库；未配置或调用失败时，研究问答会自动回退到本地证据合成。

## 企业生产化前仍需接入

1. 公司 SSO / LDAP、组织架构与研究组权限。
2. 为已实现的转写适配器配置合规允许的 ASR 密钥；默认使用支持说话人分离的文件转写模型。
3. 数据规模扩大后，可将当前 D1 检索提供器切换到 Cloudflare AI Search，无需部署 RAGFlow。
4. 组合持仓、证券主数据、公告/财报和行情数据源。
5. 合规词检测、疑似内幕信息隔离、保留期与删除审批。

## 当前智能能力边界

- 文本结构化当前采用可解释的规则提取，不需要大语言模型，适合流程验证和固定行业词表。
- 音频上传后会建立可追踪的转写任务。配置 ASR 密钥后，25MB 内音频会自动完成说话人分离、时间码逐字稿和候选结构；没有密钥时明确显示“等待管理员配置”，不会伪造结果。
- 研究问答已接入 MiniMax M3：只向模型发送权限过滤后的短证据片段与引用编号；模型不可访问完整逐字稿，失败时自动回退到本地证据合成。
- 接入模型后仍应让研究员确认结构化结果，并禁止模型直接覆盖原始谈话。
